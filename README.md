# Page Pulse — Production-Grade URL Audit Service

A small backend service that audits a URL (status, timing, headers) with the
guardrails you'd actually want in production: input validation, timeouts,
concurrency limits, per-client rate limiting, caching, structured logging,
and a CI-tested test suite.

## Live deployment

**Live URL:** https://page-pulse-99gr.onrender.com

## Running locally

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Server runs at `http://localhost:8000`. Interactive API docs at
`http://localhost:8000/docs` (auto-generated by FastAPI).

## Running tests

```bash
pytest -v
```

## Configuration

All behavior is configurable via environment variables (with sane defaults):

| Variable                   | Default | Description                                  |
|-----------------------------|---------|-----------------------------------------------|
| `CACHE_TTL_SECONDS`         | `300`   | How long an audit result is served from cache |
| `RATE_LIMIT_PER_MINUTE`     | `30`    | Requests allowed per client per minute        |
| `REQUEST_TIMEOUT_SECONDS`   | `8`     | Timeout for the outbound fetch to the target URL |
| `MAX_CONCURRENT_AUDITS`     | `20`    | Max audits processed concurrently             |

## API Contract

### `POST /audit`

Audits a URL and returns structured results. If the same URL was audited
within `CACHE_TTL_SECONDS`, the cached result is returned instantly instead
of re-fetching.

**Request**
```json
{
  "url": "https://example.com"
}
```

**Success response — `200 OK`**
```json
{
  "url": "https://example.com/",
  "status_code": 200,
  "response_time_ms": 142.3,
  "content_length_bytes": 1256,
  "server_header": "nginx",
  "content_type": "text/html; charset=UTF-8",
  "from_cache": false,
  "checked_at": "2026-07-25T05:22:52.363232+00:00"
}
```

**Error responses**

| Status | `error` code         | Meaning                                         |
|--------|-----------------------|--------------------------------------------------|
| `400`  | `INVALID_INPUT`       | Malformed request body                          |
| `422`  | (FastAPI validation)  | `url` missing or not a valid URL                |
| `429`  | `RATE_LIMITED`        | Client exceeded `RATE_LIMIT_PER_MINUTE`         |
| `502`  | `TIMEOUT`             | Target URL didn't respond within the timeout    |
| `502`  | `CONNECTION_FAILED`   | Target URL unreachable                          |
| `502`  | `REQUEST_FAILED`      | Other network-level failure                     |
| `503`  | `SERVICE_BUSY`        | `MAX_CONCURRENT_AUDITS` reached, retry shortly   |

All error responses share this shape:
```json
{
  "error": "TIMEOUT",
  "detail": "Request to https://slow.example.com timed out after 8.0s",
  "request_id": "3f9a2b7e-..."
}
```

Every response (success or error) also carries an `X-Request-ID` header for
tracing a specific request through logs.

### `GET /health`

Lightweight liveness check. Returns `{"status": "ok", "cache_entries": <n>}`.

## Design notes

- **Caching:** in-memory TTL cache, keyed by exact URL. Note this is
  per-process — fine at this scale, but wouldn't survive a restart or scale
  across multiple instances. See the accompanying architecture doc (Task B)
  for how this evolves at 10k audits/day.
- **Rate limiting:** token-bucket per client (identified by
  `X-Forwarded-For` if present, else socket IP), refilling continuously
  rather than resetting on a fixed window boundary.
- **Concurrency limiting:** an `asyncio.Semaphore` caps in-flight outbound
  fetches so a burst of audit requests can't exhaust file descriptors /
  outbound connections.
- **Errors from the *target* site (4xx/5xx) are not treated as service
  errors** — a 404 or 500 from the audited URL is still a successful audit
  (the service did its job: it found out the target returns 404/500). Only
  timeouts/connection failures/etc. against *our* service return an error.

## Deploying

Any container/PaaS host works. Two ready-made paths:

**Render / Railway (Procfile):**
```
web: uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

**Docker:**
```bash
docker build -t page-pulse .
docker run -p 8000:8000 page-pulse
```
